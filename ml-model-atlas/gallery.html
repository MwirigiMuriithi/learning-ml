00 · Gradient Descent & Optimizers

Foundations · Optimization · notebooks/00_gradient_descent_optimizers.ipynb · lessons/00_gradient_descent_optimizers.py

Family: Foundations · Optimization

Definition

Nearly every model in this course learns by *minimizing a loss function* L(θ) that measures how wrong the model is. Gradient descent repeatedly nudges the parameters θ in the direction that reduces the loss fastest (the negative gradient). Optimizers are different rules for *how big* and *in which direction* each nudge is.

Intuition

Picture a hiker in thick fog on a hillside who can only feel the slope under their feet. Plain gradient descent takes a step straight downhill. In a long narrow valley the slope mostly points at the valley *walls*, so the hiker zig-zags. Momentum remembers where it has been heading and glides along the valley floor. RMSprop/Adam rescale each direction so steep directions take small steps and flat directions take big ones.

The math

SGD       θ ← θ − η·g
Momentum  v ← β·v + g          θ ← θ − η·v
RMSprop   s ← ρ·s + (1−ρ)·g²  θ ← θ − η·g / (√s + ε)
Adam      m ← β1·m + (1−β1)·g ;  v ← β2·v + (1−β2)·g²
          θ ← θ − η · m̂ / (√v̂ + ε)      (m̂, v̂ are bias-corrected)
g = ∇L(θ) (+ noise when computed on a mini-batch)

When to use what

  • SGD (+momentum): the workhorse for CNNs; generalizes very well, needs a tuned learning rate schedule.
  • Adam / AdamW: the default for transformers, RNNs, GANs, anything noisy or badly scaled.
  • Learning rate η is the most important hyper-parameter in deep learning: too big diverges, too small crawls.

What the animation shows

Four optimizers start at the same point on the loss surface f(x,y) = x²/20 + y² (a narrow valley, 20× flatter along x), all receiving the same noisy gradients (like random mini-batches). Right: loss vs step on a log scale.

01 · Bias, Variance & Overfitting

Foundations · Generalization · notebooks/01_bias_variance_overfitting.ipynb · lessons/01_bias_variance_overfitting.py

Family: Foundations · Generalization

Definition

A model's expected test error decomposes into three parts: bias² (error from wrong assumptions: the model is too simple to capture the truth), variance (error from sensitivity to the particular training sample: the model is too flexible) and irreducible noise. *Overfitting* = low training error but high test error (variance too high); *underfitting* = both errors high (bias too high).

Intuition

Fit a straight line to a wavy signal: every training set gives nearly the same wrong line (high bias, low variance). Fit a degree-15 polynomial to 25 noisy points: it threads every point, and a *different* training set gives a wildly different curve (low bias, high variance). The sweet spot is in between.

The math

E[(y − f̂(x))²] = Bias²[f̂(x)] + Var[f̂(x)] + σ²
Bias[f̂(x)] = E[f̂(x)] − f(x)          Var[f̂(x)] = E[(f̂(x) − E[f̂(x)])²]

How to fight each problem

  • High variance: more data, regularization (lesson 04), simpler model, bagging (lesson 12), early stopping, dropout.
  • High bias: richer features, more flexible model, boosting (lesson 14), less regularization.
  • Always measure on data the model has not seen (hold-out set or k-fold cross-validation).

What the animation shows

We draw many different training sets from the same noisy process and fit polynomials of growing degree to each. Left: thin lines = individual fits (their spread is *variance*), thick line = their average, dashed = truth (the gap is *bias*). Right: the measured bias², variance and test error as complexity grows (log scale).

  • Increase noise. Why does the noise floor (dotted) rise but the bias/variance curves keep their shape?

02 · Classification Metrics, Thresholds & ROC

Foundations · Evaluation · notebooks/02_classification_metrics_roc.ipynb · lessons/02_classification_metrics_roc.py

Family: Foundations · Evaluation

Definition

A probabilistic classifier outputs a *score* per example. Turning scores into decisions needs a threshold, and every threshold produces a different confusion matrix (TP, FP, FN, TN). Metrics summarize it; the ROC curve shows all thresholds at once and AUC is the probability that a random positive is scored above a random negative.

Intuition

Loan officer: lower the approval-risk threshold and you catch more true defaulters (recall ↑) but flag more good customers (precision ↓). There is no free lunch; you pick the trade-off that matches the *cost* of each mistake.

The math

accuracy  = (TP+TN)/N                precision = TP/(TP+FP)
recall (TPR) = TP/(TP+FN)            specificity = TN/(TN+FP)
FPR = FP/(FP+TN) = 1 − specificity   F1 = 2·precision·recall/(precision+recall)
ROC: plot TPR against FPR as the threshold sweeps from 1 to 0.   AUC = area under it (0.5 = coin flip, 1 = perfect)

Practical tips

  • With imbalanced classes accuracy lies; use precision/recall, PR-AUC or cost-weighted metrics.
  • Choose the threshold on a validation set, using real business costs.
  • Always cross-validate: split into k folds, train on k−1, test on the held-out fold, average.

What the animation shows

A logistic-regression model (trained inside this file) scores 2000 synthetic loan applicants. As the decision threshold slides from strict to lenient: the score histograms with the cut line, the moving point on the ROC curve, and the live confusion matrix with all metrics.

Try this

  • Make the classes more imbalanced (change the default rate) and compare accuracy to F1.
  • Add a cost matrix (a missed default costs 10× a false alarm) and find the cost-minimizing threshold.

03 · Linear Regression

Supervised · Regression · notebooks/03_linear_regression.ipynb · lessons/03_linear_regression.py

Family: Supervised · Regression

Definition

Linear regression models a numeric target as a weighted sum of the input features plus a bias: ŷ = w·x + b. Training finds the weights that minimize the mean squared error between predictions and truth.

Intuition

Draw the straight line that passes as close as possible to all the points, where "close" means the *sum of squared vertical distances (residuals)* is as small as it can be. Squaring punishes big misses and makes the math smooth.

The math

Loss      L(w,b) = 1/(2n) Σ (w·xᵢ + b − yᵢ)²
Gradient  ∂L/∂w = 1/n Σ (ŷᵢ − yᵢ)·xᵢ        ∂L/∂b = 1/n Σ (ŷᵢ − yᵢ)
Update    w ← w − η ∂L/∂w ,  b ← b − η ∂L/∂b
Closed form (normal equation): w = (XᵀX)⁻¹ Xᵀ y

Assumptions & pitfalls

  • Linear relationship; independent errors with constant variance; no extreme multicollinearity.
  • Sensitive to outliers (squared error). Scale features before gradient descent.
  • Coefficients are only interpretable when features are not heavily correlated.

What the animation shows

Left: the line rotating and shifting toward the data, red segments are the residuals being squared. Right: the loss surface over (w,b) with the optimizer's path sliding down the elongated valley. Afterwards the script fits a 4-feature *house price* model both ways (gradient descent vs normal equation) and prints the coefficients.

Try this

  • Standardize x before descending: the valley becomes round and convergence is far faster.
  • Add one huge outlier to the data and watch the line get dragged toward it.

04 · Regularization: Ridge, Lasso & Elastic Net

Supervised · Regression (penalized linear models) · notebooks/04_regularization_ridge_lasso.ipynb · lessons/04_regularization_ridge_lasso.py

Family: Supervised · Regression (penalized linear models)

Definition

Regularization adds a penalty on the size of the weights to the loss so the model cannot over-use any feature. Ridge (L2) shrinks all weights smoothly toward zero; Lasso (L1) can set weights *exactly* to zero (automatic feature selection); Elastic Net mixes both.

Intuition

With many correlated or noisy features, unpenalized regression happily assigns large opposing weights that fit noise. The penalty is a budget: weights must "pay" for being large, so only features that truly help earn a big weight. The L1 penalty has corners on the axes, so the optimum often lands exactly on a corner, which means a zero weight.

The math

minimize   1/(2n) ||y − Xw||²  +  λ [ α·||w||₁ + (1−α)/2·||w||₂² ]
Ridge (α=0): w = (XᵀX/n + λI)⁻¹ Xᵀy/n
Lasso/Elastic Net via coordinate descent:  wⱼ ← S(ρⱼ, λα) / (1 + λ(1−α)),
ρⱼ = 1/n Xⱼᵀ(residual + Xⱼwⱼ),  S(r,t) = sign(r)·max(|r|−t, 0)   (soft-thresholding)

Practical tips

  • Always standardize features first, otherwise the penalty is unfair across units.
  • Choose λ by cross-validation (the U-shaped test-error curve on the right).
  • Lasso arbitrarily picks one of several correlated features; Elastic Net keeps groups together.

What the animation shows

We use the 4 real house-price features plus 6 pure-noise columns. As λ grows: left, ridge paths shrink gradually; middle, lasso paths hit zero one by one, noise features first; right, test error forms a U shape.

Try this

  • Change alpha for the elastic net and see how the path shape morphs between ridge and lasso.
  • Make training smaller (50 rows) and see how much more regularization helps.

05 · Logistic Regression

Supervised · Classification (linear) · notebooks/05_logistic_regression.ipynb · lessons/05_logistic_regression.py

Family: Supervised · Classification (linear)

Definition

Despite the name, logistic regression is a *classifier*. It computes a linear score z = w·x + b and squashes it through the sigmoid σ(z) = 1/(1+e⁻ᶻ) to get a probability P(y=1 | x). The decision boundary (P = 0.5) is the straight line w·x + b = 0.

Intuition

Linear regression extended to probabilities. Far on one side of the line the model is confident (P≈0 or 1); near the line it is unsure (P≈0.5). Training pushes the line to put defaulters on one side and good borrowers on the other, punishing *confident mistakes* very hard.

The math

P(y=1|x) = σ(w·x + b)
Loss (binary cross-entropy / negative log-likelihood):  L = −1/n Σ [ y log p + (1−y) log(1−p) ]
Gradient (beautifully simple):  ∂L/∂w = 1/n Σ (pᵢ − yᵢ) xᵢ ,   ∂L/∂b = 1/n Σ (pᵢ − yᵢ)
Multi-class: softmax instead of sigmoid.  Regularize with an L2/L1 penalty exactly like lesson 04.

Strengths & weaknesses

  • Fast, convex (a single global optimum), well-calibrated probabilities, interpretable (odds ratio = e^w).
  • Only linear boundaries unless you add polynomial/interaction features; needs scaled inputs for gradient descent.

What the animation shows

Loan-default data (income vs debt ratio). Watch the probability map (blue = repay, orange = default) and the black P=0.5 decision line rotate from a random starting guess to the best separator; right: loss falls, accuracy rises.

06 · The Perceptron

Supervised · Classification (linear), the ancestor of neural networks · notebooks/06_perceptron.ipynb · lessons/06_perceptron.py

Family: Supervised · Classification (linear), the ancestor of neural networks

Definition

The perceptron (Rosenblatt, 1958) is a single artificial neuron: ŷ = sign(w·x + b). It learns by looking at one example at a time and, only when it makes a mistake, nudging the boundary toward classifying that example correctly.

Intuition

If a point is on the wrong side of the line, pull the line toward it (add the point's vector to w if it is a positive example, subtract if it is negative). Repeat. If the classes can be separated by a line, this is *guaranteed* to stop.

The math

ŷ = sign(w·x + b)           labels y ∈ {−1, +1}
if y (w·x + b) ≤ 0 :        w ← w + η y x ,   b ← b + η y        (otherwise do nothing)
Perceptron convergence theorem: if a separating margin γ exists and ||x|| ≤ R, at most (R/γ)² mistakes are ever made.

Limitations (and why they matter)

  • If the data is not linearly separable (like XOR) it never converges and keeps oscillating.

    • That failure (Minsky & Papert, 1969) motivated multi-layer networks (lesson 15).

  • No probabilities, and the final line is just *some* separator, not the best one (SVMs, lesson 10, fix that).

What the animation shows

One frame per weight update. Left: linearly separable customers; the circled point is the mistake being fixed and the boundary jumps until it separates the classes. Right: XOR data, where no line works and the boundary keeps flailing.

07 · k-Nearest Neighbors (k-NN)

Supervised · Classification / Regression (instance-based, non-parametric) · notebooks/07_k_nearest_neighbors.ipynb · lessons/07_k_nearest_neighbors.py

Family: Supervised · Classification / Regression (instance-based, non-parametric)

Definition

k-NN does no training at all. To classify a new point it finds the k most similar stored examples (nearest by distance) and takes a majority vote (classification) or an average (regression). The "model" *is* the training data.

Intuition

"Tell me who your neighbours are and I'll tell you who you are." A small k follows every quirk of the data (low bias, high variance); a large k blurs everything toward the global majority (high bias, low variance).

The math

d(x, xᵢ) = ||x − xᵢ||₂      (or Manhattan, cosine, ...)
ŷ(x) = argmax_c  Σ_{i ∈ N_k(x)} 1[yᵢ = c]            regression: ŷ = mean of the k neighbours' y
Weighted variant: each neighbour votes with weight 1/d.

Practical tips

  • Scale features (distance is dominated by large-range features). Beware the curse of dimensionality.
  • Prediction cost grows with the dataset (use KD-trees / approximate NN such as FAISS or HNSW).
  • k chosen by cross-validation; odd k avoids ties in binary problems.

What the animations show

1. 07_k_nearest_neighbors.gif: the decision regions for k = 1 … 61 on noisy moons, plus train/test accuracy. k=1 is a jagged island map with 100 % training accuracy; huge k is too smooth. 2. 07_k_nearest_neighbors_query.gif: a query point glides through the data; lines connect it to its 5 neighbours who vote.

08 · Naive Bayes

Supervised · Classification (probabilistic, generative) · notebooks/08_naive_bayes.ipynb · lessons/08_naive_bayes.py

Family: Supervised · Classification (probabilistic, generative)

Definition

Naive Bayes applies Bayes' theorem to classification and makes one big simplifying ("naive") assumption: given the class, all features are independent. It models how each class *generates* its features, then inverts that to get P(class | features).

Intuition

A spam filter learns: spam emails usually have many links and lots of CAPS; ham rarely does. For a new email, multiply how plausible each observed feature is under "spam" by the spam prior, do the same for "ham", and normalise. The independence assumption is false (links and CAPS correlate) but the ranking of classes is often still right, so it works surprisingly well.

The math

P(c | x) ∝ P(c) · Π_j P(x_j | c)
Gaussian NB:   P(x_j | c) = N(x_j ; μ_cj , σ²_cj)     (parameters = per-class mean and variance, just counts!)
Compute in log-space:  log P(c) + Σ_j log P(x_j | c)   to avoid underflow.
Text (multinomial NB): P(word | c) = (count + α) / (total + α·V)   with Laplace smoothing α.

Strengths & weaknesses

  • Extremely fast, works with tiny datasets and huge feature spaces (text), naturally multi-class, online-updatable.
  • Probabilities are poorly calibrated (over-confident); can't learn feature interactions.

What the animation shows

Spam data (links vs CAPS ratio). As more training emails arrive (4 → 400) watch the fitted per-class Gaussians (ellipses = 2σ) sharpen, the posterior map stabilise, and (right) the 1-D likelihoods P(links | class).

09 · Linear & Quadratic Discriminant Analysis (LDA / QDA)

Supervised · Classification (generative, Gaussian class models) · notebooks/09_discriminant_analysis_lda_qda.ipynb · lessons/09_discriminant_analysis_lda_qda.py

Family: Supervised · Classification (generative, Gaussian class models)

Definition

LDA and QDA model each class as a multivariate Gaussian N(μ_c, Σ_c) and classify with Bayes' rule. LDA assumes all classes share the *same* covariance matrix, which gives a linear boundary. QDA lets every class have its own covariance, which gives a quadratic (curved) boundary.

Intuition

Unlike naive Bayes, these models keep correlations between features (tilted ellipses, not axis-aligned ones). LDA pools all the data to estimate one shape, which is stable with few samples. QDA is more flexible but needs more data (it estimates d² numbers per class).

The math

discriminant  δ_c(x) = −½ log|Σ_c| − ½ (x−μ_c)ᵀ Σ_c⁻¹ (x−μ_c) + log π_c        predict argmax_c δ_c(x)
LDA: Σ_c = Σ (pooled)  =>  the quadratic terms cancel, leaving the linear  w·x + b
LDA doubles as supervised dimensionality reduction: project onto the directions maximizing between-class / within-class scatter.

When to use

  • Small data + roughly Gaussian classes: LDA is hard to beat. Classes with clearly different spreads: QDA.
  • Regularized discriminant analysis (shrink Σ_c toward Σ) interpolates between the two.

What the animation shows

Two classes whose covariances start identical and gradually become different (t: 0 → 1). Left: LDA's straight boundary cannot adapt; right: QDA's boundary curves around the narrower class. Ellipses = fitted 2σ class shapes.

  • Make the means identical but the covariances different: LDA fails completely, QDA still works.

10 · Support Vector Machines (SVM) & the Kernel Trick

Supervised · Classification (margin-based) · notebooks/10_support_vector_machine.ipynb · lessons/10_support_vector_machine.py

Family: Supervised · Classification (margin-based)

Definition

An SVM finds the decision boundary with the largest margin: the widest street separating the two classes. Only the points touching the street edges, the support vectors, matter; every other point could be deleted without changing the model. The kernel trick lets the same algorithm draw curved boundaries by implicitly mapping points into a high-dimensional space.

Intuition

Many lines separate two classes, but the one farthest from both is the most robust to noise. If the classes overlap, the soft margin parameter C says how much you are willing to pay for points inside the street or misclassified (small C = wide, tolerant street; large C = strict, may overfit).

The math

Primal (soft margin):  min ½||w||² + C Σ max(0, 1 − yᵢ(w·xᵢ + b))        (hinge loss)
Dual:                  max Σ αᵢ − ½ Σᵢⱼ αᵢ αⱼ yᵢ yⱼ K(xᵢ,xⱼ)    s.t.  0 ≤ αᵢ ≤ C
Decision:              f(x) = Σ αᵢ yᵢ K(xᵢ, x) + b           support vectors = points with αᵢ > 0
Kernels:               linear  K = x·x' ;  RBF  K = exp(−γ||x − x'||²) ;  polynomial  K = (x·x' + 1)ᵈ
Here we absorb b into the kernel (K+1) and solve the dual by coordinate ascent, one αᵢ at a time:
                       αᵢ ← clip(αᵢ + (1 − yᵢ f(xᵢ)) / Qᵢᵢ , 0, C)

Practical tips

  • Scale features. Tune C and γ together by grid search. Great on small/medium data; O(n²–n³) training cost.
  • Large γ = every point is its own island (overfit). Small γ ≈ linear.

What the animations show

1. 10_support_vector_machine.gif: dual coordinate ascent epoch by epoch. Left: linear kernel on overlapping blobs; right: RBF kernel on moons. Solid line = boundary f=0, dashed = margins f=±1, ringed points = support vectors. 2. 10_support_vector_machine_hyper.gif: how γ (flexibility) changes the RBF boundary from nearly linear to overfit.

  • Plot accuracy against C on a log scale for both datasets.
  • Use the polynomial kernel (degree 3) on the circles dataset.

11 · Decision Trees (CART)

Supervised · Classification & Regression (non-linear, rule-based) · notebooks/11_decision_tree.ipynb · lessons/11_decision_tree.py

Family: Supervised · Classification & Regression (non-linear, rule-based)

Definition

A decision tree asks a sequence of yes/no questions about single features ("is income ≤ 43?"), splitting the data into ever purer groups, until a leaf makes a prediction (majority class, or the mean for regression). It is the same as a set of if/else rules and is the most human-readable ML model.

Intuition

Twenty-questions for data. At each node, try every feature and every threshold and choose the split that makes the two children as *pure* as possible. Recurse until a depth limit or until nodes are pure. Deep trees memorise the training set, so depth/leaf-size is the main complexity dial (and the reason for pruning).

The math

Gini impurity   G = 1 − Σ_c p_c²              Entropy   H = − Σ_c p_c log p_c
Best split      argmin over (feature j, threshold t) of   n_L·G(L) + n_R·G(R)
Regression      same recipe with variance (SSE) instead of Gini; leaf = mean of y
Feature importance = total impurity reduction attributed to that feature.

Strengths & weaknesses

  • No scaling needed, handles mixed types/missing values (with tweaks), captures interactions, interpretable.
  • Unstable (small data changes → different tree), axis-aligned boundaries only, overfits easily.

    • Ensembles (lessons 12–14) fix instability.

What the animations show

1. 11_decision_tree.gif: the tree grows level by level on noisy moons; black lines are the chosen split thresholds (thicker = earlier), shaded regions are the predictions. Right: train accuracy keeps climbing while test accuracy peaks then falls. 2. 11_decision_tree_regression.gif: a regression tree approximating a smooth curve with staircase steps. The console prints the rules of a depth-3 tree on loan data.

12 · Random Forest (Bagging)

Supervised · Classification & Regression (ensemble, variance reduction) · notebooks/12_random_forest.ipynb · lessons/12_random_forest.py

Family: Supervised · Classification & Regression (ensemble, variance reduction)

Definition

A random forest trains many *deep* decision trees, each on a different bootstrap sample (rows drawn with replacement) and each split considering only a random subset of features, then averages their votes. This is bagging plus feature randomness.

Intuition

One deep tree has low bias but very high variance. Averaging many *different* high-variance trees cancels their individual mistakes: the errors are partly independent, so the average is far steadier. Randomness decorrelates the trees, which is what makes averaging effective (variance of the mean ≈ ρσ² + (1−ρ)σ²/B).

The math

for b = 1..B:  draw bootstrap sample D_b (n rows with replacement), grow tree T_b (random m features per split)
prediction:    classification = majority vote / mean of probabilities ;  regression = mean
Out-of-bag (OOB) estimate: each row is left out of ≈ 36.8 % of the trees, so score it with only those trees -> a free validation score.
Feature importance: mean impurity decrease, or permutation importance.

Practical tips

  • Few hyper-parameters, hard to overfit by adding trees, strong default for tabular data, no scaling needed.
  • Slower/larger than a single tree; less interpretable; poor at extrapolating beyond the training range.

What the animation shows

Left: the forest's averaged probability map as trees are added (1 → 60), smoothing from a jagged single-tree map into a gentle boundary. Middle: the newest single tree on its own (jagged!). Right: test accuracy and OOB accuracy converge.

13 · AdaBoost

Supervised · Classification (ensemble, boosting) · notebooks/13_adaboost.ipynb · lessons/13_adaboost.py

Family: Supervised · Classification (ensemble, boosting)

Definition

AdaBoost builds a strong classifier from many weak learners (here, one-split "stumps" barely better than guessing) trained *sequentially*. After each round it raises the weights of the examples that were misclassified so the next stump is forced to focus on the hard cases. The final prediction is a weighted vote.

Intuition

A team of mediocre specialists. The first stump draws one line. Points it got wrong become heavier (they appear bigger on screen), so the second stump concentrates on them, and so on. Stumps that were more accurate get a louder voice (larger α).

The math

init   wᵢ = 1/n
for t = 1..T:  fit stump h_t on weighted data;   ε_t = Σ wᵢ·1[h_t(xᵢ) ≠ yᵢ]
               α_t = ½ ln((1 − ε_t)/ε_t)
               wᵢ ← wᵢ · exp(−α_t yᵢ h_t(xᵢ)) , then normalise      (y, h ∈ {−1,+1})
final  H(x) = sign( Σ_t α_t h_t(x) )
AdaBoost = gradient boosting on the exponential loss; sensitive to label noise and outliers (they get exponentially heavy).

What the animation shows

A ring-shaped class that no single vertical/horizontal line can separate. Left: point size = current weight, black line = the newest stump, background = the ensemble's current decision. Right: the ensemble's accuracy climbs while each stump's own weighted error stays close to 0.5.

14 · Gradient Boosting (GBM / XGBoost / LightGBM idea)

Supervised · Regression & Classification (ensemble, boosting) · notebooks/14_gradient_boosting.ipynb · lessons/14_gradient_boosting.py

Family: Supervised · Regression & Classification (ensemble, boosting)

Definition

Gradient boosting builds a model as a sum of small trees added one at a time, where each new tree is trained to predict the negative gradient of the loss (for squared error: simply the *residuals*, the current mistakes). It is gradient descent performed in function space.

Intuition

Start with a crude guess (the mean). Look at what is still wrong (residuals), fit a small tree to explain part of that error, add a fraction (the learning rate) of it, and repeat. Each tree is a small correction, and many corrections add up to a sharp, accurate model.

The math

F₀(x) = mean(y)       (classification: log-odds of the base rate)
for m = 1..M:
    rᵢ = −∂L(yᵢ, F(xᵢ))/∂F(xᵢ)           squared error: rᵢ = yᵢ − F(xᵢ);   log-loss: rᵢ = yᵢ − σ(F(xᵢ))
    fit a shallow tree h_m to the pseudo-residuals r
    F_m(x) = F_{m−1}(x) + η · h_m(x)       η = learning rate (shrinkage), typically 0.01–0.3
XGBoost/LightGBM add: second-order (Newton) steps, regularized leaf values, histogram splits, subsampling.

Practical tips

  • Usually the best off-the-shelf model for tabular data. Tune learning rate × number of trees, tree depth (3–8), subsampling; use early stopping.
  • Smaller η + more trees = better but slower. Sensitive to noisy labels if too many rounds.

What the animations show

1. 14_gradient_boosting.gif (regression): left, prediction F_m hugging the curve; middle, the *residuals* and the small tree fitted to them; right, train/test error. The residuals shrink and become noise. 2. 14_gradient_boosting_classification.gif: the same idea with log-loss on moons: the probability map sculpts itself round by round.

  • Use depth-1 stumps vs depth-4 trees at the same number of rounds.

15 · Neural Networks (MLP) & Backpropagation

Supervised · Deep learning (multi-layer perceptron) · notebooks/15_neural_network_backprop.ipynb · lessons/15_neural_network_backprop.py

Family: Supervised · Deep learning (multi-layer perceptron)

Definition

A multi-layer perceptron stacks layers of neurons. Each layer computes a linear map followed by a non-linear activation, so the network can bend space and learn *any* smooth decision boundary (universal approximation). Backpropagation is the chain rule applied efficiently from the loss back to every weight, and gradient descent then updates them all.

Intuition

The first layers learn to re-describe the inputs (bend and stretch the plane) so that the last layer, a plain linear classifier, can separate the classes. Without non-linear activations, stacked layers collapse into one linear layer.

The math (2 hidden layers, tanh, softmax + cross-entropy)

a1 = tanh(X W1 + b1)      a2 = tanh(a1 W2 + b2)      z = a2 W3 + b3      p = softmax(z)
L = −1/n Σ log p[i, yᵢ]
Backward:  dz  = (p − onehot(y)) / n
           dW3 = a2ᵀ dz            da2 = dz W3ᵀ      dz2 = da2 ⊙ (1 − a2²)
           dW2 = a1ᵀ dz2           da1 = dz2 W2ᵀ     dz1 = da1 ⊙ (1 − a1²)
           dW1 = Xᵀ dz1            (biases: column sums)        then  W ← W − η·dW (here with Adam)
This file writes every line of that by hand and verifies it against numerical gradients.

Practical tips

  • Standardize inputs; initialize with Xavier/He scaling; ReLU/GELU for deep nets; Adam is a strong default.
  • Overfitting control: weight decay, dropout, early stopping, more data. Batch/layer norm stabilize deep nets.

What the animation shows

A 3-arm spiral, which no linear model can classify. Left: the decision regions the network carves out over training; right: loss and accuracy curves. Early on the boundaries are almost straight lines; then they twist to follow the spirals.

16 · Convolutional Neural Networks (CNN)

Supervised · Deep learning for images / grids · notebooks/16_convolutional_neural_network.ipynb · lessons/16_convolutional_neural_network.py

Family: Supervised · Deep learning for images / grids

Definition

A CNN processes images with convolution layers: small learnable filters (here 3×3) slide across the image, and each filter produces a *feature map* showing where its pattern occurs. Pooling shrinks the maps and adds tolerance to small shifts. Dense layers at the end classify. Weight sharing makes CNNs far more efficient than fully-connected nets on images.

Intuition

A filter is a tiny pattern detector (an edge, a corner, a stroke direction). Sliding it over the picture asks "is this pattern here?" at every position. Stacking layers builds from edges → textures → parts → objects. We train on 8×8 images of strokes (horizontal, vertical, two diagonals) and watch the filters turn into oriented-edge detectors by themselves.

The math

conv:   Z[f,i,j] = Σ_{k,l} W[f,k,l] · X[i+k, j+l] + b_f          (cross-correlation; "valid" padding)
ReLU:   A = max(Z, 0)             max-pool 2×2:  M[f,i,j] = max of the 2×2 block of A
dense:  logits = flatten(M) W₂ + b₂ ;   softmax + cross-entropy
Backprop through the layers by hand:  dense → un-flatten → route the gradient to the arg-max of each pooling window
→ multiply by 1[Z>0] → dW[f] = Σ over positions of  dZ[f,i,j] · (image patch at i,j)
Output size = (N − K + 2P)/S + 1.

17 · Recurrent Neural Networks (RNN) & Backprop-Through-Time

Supervised · Deep learning for sequences · notebooks/17_recurrent_neural_network.ipynb · lessons/17_recurrent_neural_network.py

Family: Supervised · Deep learning for sequences

Definition

An RNN reads a sequence one element at a time and keeps a hidden state hₜ, a running summary of everything seen so far. The same weights are reused at every time step, so it handles sequences of any length (time series, text, sensor streams).

Intuition

Reading a sentence word by word while keeping a mental note of the story so far. At each step the note is updated from the new word and the previous note. To train, we "unroll" the network through time (one copy per step, sharing weights) and backpropagate through all the copies: backpropagation through time (BPTT).

The math

hₜ = tanh(xₜ Wₓₕ + hₜ₋₁ Wₕₕ + b)           ŷₜ = hₜ W_y + b_y
L = 1/T Σₜ (ŷₜ − yₜ)²                       gradient flows backwards through every hₜ
∂L/∂Wₕₕ = Σₜ  ... Π (Wₕₕᵀ · diag(1 − h²)) ...      repeated multiplication => gradients vanish (<1) or explode (>1)
Fixes: gradient clipping (used here), gated cells (LSTM/GRU, lesson 18), attention (lesson 19).
This file uses the autograd engine in mlatlas/nn.py, so BPTT is automatic; read the 6-line forward pass.

Practical tips

  • Clip gradient norm. Use LSTM/GRU for anything with long-range dependencies. Transformers have mostly replaced RNNs for text.
  • For forecasting, teacher forcing (feed the true previous value) is used in training; at inference you feed back predictions.

What the animation shows

A noisy two-frequency "seasonal demand" signal. Top-left: the RNN's one-step-ahead prediction (red) improving over the true signal (black). Right: the heat-map of the 16 hidden units over time (the network's memory), bottom-left: loss curve.

18 · LSTM & GRU: Gated Memory

Supervised · Deep learning for sequences · notebooks/18_lstm_gru_gated_memory.ipynb · lessons/18_lstm_gru_gated_memory.py

Family: Supervised · Deep learning for sequences

Definition

LSTM (Hochreiter & Schmidhuber, 1997) and GRU (Cho et al., 2014) are recurrent cells with gates: learned sigmoid switches that decide what to write into memory, what to keep and what to reveal. They solve the vanishing-gradient problem of plain RNNs because the memory (cell state) can be carried across many steps almost untouched, giving gradients a "highway".

Intuition

A plain RNN rewrites its whole memory every step, so an early signal is quickly overwritten. An LSTM has a notebook (cell state cₜ) with three controls: the forget gate (erase old notes?), the input gate (write new notes?), the output gate (read the notes out now?). Here the task is a pure memory test: *the first input is a +1 or −1 signal, followed by 29 steps of random noise; at the end, report the sign of the first input.*

The math (LSTM)

[i, f, o, g] = [x, h] W + b         i,f,o = σ(·)   g = tanh(·)
cₜ = f ⊙ cₜ₋₁ + i ⊙ g               (additive update = gradient highway)
hₜ = o ⊙ tanh(cₜ)
GRU (fewer parameters, no separate cell):  z = σ([x,h]Wz) , r = σ([x,h]Wr) , h̃ = tanh([x, r⊙h]W) , h = (1−z)⊙h + z⊙h̃
Forget-gate bias initialised to +1 so the cell remembers by default.

Practical tips

  • LSTM/GRU are the standard for sequential data when transformers are overkill (streams, small data, on-device).
  • GRU is faster and often equal in accuracy; LSTM can be better for very long dependencies.

What the animation shows

Left: test accuracy during training for a vanilla RNN, GRU and LSTM on the memory task (50 % = guessing). Right: the LSTM's input, forget, output gates and cell state over the 30 time steps for one sequence. Watch the cell state lock in the first signal and the forget gate stay open.

19 · Attention & the Transformer

Supervised · Deep learning (sequence → sequence, language, vision) · notebooks/19_attention_transformer.ipynb · lessons/19_attention_transformer.py

Family: Supervised · Deep learning (sequence → sequence, language, vision)

Definition

Attention lets every position in a sequence look at every other position and pull in the information it needs, weighted by relevance. A Transformer stacks attention + feed-forward blocks with residual connections and layer normalization. There is no recurrence, so all positions are processed in parallel, which is what lets models scale to GPT/BERT size.

Intuition

Each token asks a question (query), advertises what it contains (key) and carries a payload (value). Similarity between a query and every key decides how much of each value is mixed in (softmax weights). In this lesson the model must find *the one flagged digit* in a sequence of 8 digits and report it. We train a tiny 1-layer transformer encoder and watch its attention learn to lock onto the flagged token.

The math

Q = XW_q ,  K = XW_k ,  V = XW_v
Attention(Q,K,V) = softmax( Q Kᵀ / √d ) V               (√d keeps the softmax from saturating)
Multi-head: run h attention "heads" on d/h-dimensional slices, concatenate, project with W_o
Block:  X ← LayerNorm(X + Attention(X))      X ← LayerNorm(X + FFN(X)),   FFN = ReLU(XW₁+b₁)W₂ + b₂
Position: attention is order-blind, so add positional information (sinusoidal  sin/cos(pos/10000^(2i/d))  or learned).
Causal mask (GPT-style) sets future positions' scores to −∞.
Cost: O(n²) in sequence length, the reason for long-context research (sparse/linear attention, FlashAttention).

Practical tips

  • Warm-up + Adam(W), pre-LayerNorm, dropout, large batches. Pretrain on lots of data, then fine-tune.
  • Also dominates vision (ViT), audio, protein folding and more.

What the animation shows

Rows are 6 fixed test sequences; columns the 8 digit positions (the red frame marks the flagged one). The colour shows how strongly the classification token attends to each position. Initially attention is spread out; as training progresses it snaps onto the flagged digit. Right: loss and accuracy. 20 · Autoencoders

Unsupervised · Representation learning / dimensionality reduction · notebooks/20_autoencoder.ipynb · lessons/20_autoencoder.py

Family: Unsupervised · Representation learning / dimensionality reduction

Definition

An autoencoder is a neural network trained to reconstruct its own input through a narrow bottleneck. The *encoder* compresses x into a short code z; the *decoder* rebuilds x̂ from z. No labels are needed: the target is the input itself.

Intuition

If the data really lives on a low-dimensional surface (a curve in 2-D), the bottleneck forces the network to discover coordinates *along* that surface. Here noisy sensor points lie on a bent arc; a 1-number bottleneck must learn "how far along the arc am I?". It is a non-linear PCA: with linear layers it recovers PCA exactly.

The math

z = enc(x) = W₂ tanh(W₁x + b₁) + b₂          x̂ = dec(z)
L = 1/n Σ ||x − x̂||²
Variants: denoising AE (corrupt x, reconstruct clean x), sparse AE (penalty on z), contractive AE, convolutional AE, VAE (lesson 21).
Uses: compression, denoising, anomaly detection (large reconstruction error = unusual), feature learning, pre-training.

What the animation shows

Left: data (grey), each point's reconstruction (coloured by its latent value z) and the decoder's learned curve (black), the manifold it discovered. Middle: histogram of the 1-D codes. Right: reconstruction loss. The decoder curve starts as a blob near the mean and unfolds along the arc.

21 · Variational Autoencoder (VAE)

Unsupervised · Generative model · notebooks/21_variational_autoencoder.ipynb · lessons/21_variational_autoencoder.py

Family: Unsupervised · Generative model

Definition

A VAE is an autoencoder whose code is a *probability distribution*, not a point: the encoder outputs a mean μ and variance σ² and we sample z ~ N(μ, σ²). An extra loss pulls those distributions toward a standard normal prior N(0, I). The latent space becomes smooth and dense, so sampling z from the prior and decoding generates brand-new, realistic data.

Intuition

A plain autoencoder can scatter codes anywhere, leaving holes where the decoder produces garbage. The VAE's KL penalty packs all codes into one tidy blob around the origin, and sampling noise forces nearby codes to decode to similar outputs. Here the data is two interleaved moons; we learn a 2-D latent space and then generate new moon points from pure noise.

The math

encoder: x -> (μ, log σ²)          reparameterization trick:  z = μ + σ ⊙ ε ,  ε ~ N(0, I)   (makes sampling differentiable)
decoder: z -> x̂
ELBO loss:  L = E||x − x̂||² / (2s²)  +  KL( N(μ,σ²) || N(0,I) ),   KL = −½ Σ (1 + log σ² − μ² − σ²)
Trade-off: reconstruction (accuracy) vs KL (regularity). β-VAE scales the KL term to disentangle factors.

Practical tips

  • Output tends to be blurry for images (Gaussian likelihood); VQ-VAE and diffusion models improve on that.
  • Watch for "posterior collapse" (KL → 0, decoder ignores z): anneal β from 0 up.

What the animation shows

Left: the 2-D latent space; every training point's encoded mean, coloured by moon, and the N(0,1) prior circle. Middle: data (grey) vs points *generated from random noise* (red). Right: reconstruction and KL loss terms. Early generations are a blob; later they concentrate around the two moons. Notice that some samples still land in the gap between them: a VAE trades sharpness for coverage, one reason GANs and diffusion models give crisper samples.

  • Walk a straight line in latent space between a point of each moon and decode it (latent interpolation).
  • Set the KL weight to 0 (plain AE) and sample from the prior: how many generated points are off the moons?

22 · Generative Adversarial Networks (GAN)

Unsupervised · Generative model (adversarial training) · notebooks/22_generative_adversarial_network.ipynb · lessons/22_generative_adversarial_network.py

Family: Unsupervised · Generative model (adversarial training)

Definition

A GAN trains two networks in a game. The generator G turns random noise into fake samples; the discriminator D tries to tell real samples from fakes. G is rewarded when D is fooled; D is rewarded when it is not. At equilibrium G's samples match the real distribution and D can only guess (output 0.5).

Intuition

A counterfeiter and a detective. As the detective gets better at spotting fakes, the counterfeiter must make better ones. We use the simplest possible setting, 1-D data, so you can see everything: the real data are two bumps (e.g. commuter arrival times: morning and evening rush), and G must learn to map a single bell-curve of noise onto *two* bumps.

The math

D(x) = P(x is real)          G(z), z ~ N(0, I)
min_G max_D  E_x[log D(x)] + E_z[log(1 − D(G(z)))]
In practice D minimizes BCE(real→1, fake→0); G uses the "non-saturating" loss  −log D(G(z))  (stronger gradients early on).
Optimal discriminator for fixed G:  D*(x) = p_data(x) / (p_data(x) + p_G(x))     ->  the green curve below
Note: the generated bumps come out a little narrower/spikier than the real ones, a mild form of mode collapse that is typical of plain GANs.
Known troubles: mode collapse (G covers only one bump), oscillating training, vanishing gradients. Remedies: WGAN, spectral norm, careful lr.

Left: histogram of real data (grey) vs generated samples (orange) with the discriminator's belief D(x) (green line). Middle: the generator's learned mapping z → G(z); it must become a staircase to make two bumps from one (the noise has 4 dimensions so it can also spread each bump). Right: the two losses oscillating (healthy for GANs).

23 · K-Means Clustering

Unsupervised · Clustering (centroid-based) · notebooks/23_k_means.ipynb · lessons/23_k_means.py

Family: Unsupervised · Clustering (centroid-based)

Definition

K-means partitions n points into k clusters by repeatedly (1) assigning each point to its nearest centroid and (2) moving each centroid to the mean of the points assigned to it (Lloyd's algorithm). It minimizes the within-cluster sum of squares (inertia).

Intuition

Place k pins on the map at random. Every customer goes to the nearest pin; then move each pin to the centre of its customers; the borders (Voronoi cells) shift, so repeat. It always converges, but maybe to a *local* optimum, so initialisation matters (k-means++ spreads the starting pins).

The math

assign:  cᵢ = argmin_k ||xᵢ − μ_k||²              update:  μ_k = mean{ xᵢ : cᵢ = k }
objective (inertia): J = Σᵢ ||xᵢ − μ_{cᵢ}||²   (never increases; guaranteed to converge)
Choosing k: elbow method (where J stops dropping fast), silhouette score, gap statistic, or business needs.
k-means++: first centre uniformly at random, each next centre sampled with probability ∝ D(x)² (distance to nearest chosen centre).

Practical tips

  • Scale features; assumes round, similarly sized clusters; sensitive to outliers (use k-medoids / GMM / DBSCAN otherwise).
  • Use for customer segmentation, colour quantization, vector quantization, initialising other models.

What the animation shows

Mall customers (annual income vs spending score) with a deliberately bad random start. Each iteration has two frames: assign (points recolour) then update (centroids jump to the cluster means, arrows show the move). Right: inertia plummets then flat-lines. The console prints the elbow curve and compares k-means++.

24 · Hierarchical (Agglomerative) Clustering

Unsupervised · Clustering (tree-based) · notebooks/24_hierarchical_clustering.ipynb · lessons/24_hierarchical_clustering.py

Family: Unsupervised · Clustering (tree-based)

Definition

Start with every point as its own cluster, then repeatedly merge the two closest clusters until only one remains. The sequence of merges forms a tree, the dendrogram. Cutting the tree at a chosen height gives any number of clusters, so you do not need to choose k in advance.

Intuition

Building a family tree from similarity: the two most similar customers pair up first, then similar pairs merge, and so on. The *height* of a merge is how far apart the two groups were; a very tall merge signals "these really are different groups", so cut just below it.

The math

cluster distance ("linkage"):
  single    d(A,B) = min d(a,b)          (can chain; finds elongated clusters)
  complete  d(A,B) = max d(a,b)          (compact clusters)
  average   d(A,B) = mean d(a,b)
  ward      merge the pair giving the smallest increase in total within-cluster variance:  Δ = |A||B|/(|A|+|B|) ||μ_A − μ_B||²
naive cost O(n³), O(n² log n) with priority queues. Needs the full distance matrix (so ≈ up to tens of thousands of points).

Practical tips

  • Great for small data, taxonomies, gene expression, and when you want to explore several granularities. Use scaling.
  • Ward ≈ k-means-like compact clusters; single linkage for chains.

What the animation shows

36 customers; each frame performs one merge. Left: current clusters (singletons grey, merged clusters coloured, the newest merge circled). Right: the dendrogram growing from the bottom, with the red link as the latest merge.

  • Switch linkage="single" and see long chain-like merges.
  • Draw a horizontal cut at distance h and count clusters.

25 · DBSCAN (Density-Based Clustering)

Unsupervised · Clustering (density-based) + outlier detection · notebooks/25_dbscan.ipynb · lessons/25_dbscan.py

Family: Unsupervised · Clustering (density-based) + outlier detection

Definition

DBSCAN groups points that are packed closely together and labels isolated points as noise. It needs two numbers: a radius ε and a minimum neighbourhood size minPts. Clusters can have *any shape*, and the number of clusters is discovered, not chosen.

Intuition

Think of a crowd at a festival: dense crowds are clusters, lone wanderers are noise. A core point has ≥ minPts neighbours within ε. A cluster grows by hopping from core point to core point (density-reachability); border points are within ε of a core point but not dense themselves.

The math

N_ε(p) = { q : ||p − q|| ≤ ε }          p is core  ⇔  |N_ε(p)| ≥ minPts
expand: start at an unvisited core point, give it a new cluster id, and recursively add all points in the neighbourhoods of the core points reached.
Choosing ε: plot the sorted distance of every point to its k-th nearest neighbour (k = minPts) and pick the "knee" (right panel).
Complexity O(n log n) with a spatial index. HDBSCAN removes the single-ε limitation (varying densities).

Practical tips

  • Scale features first. Struggles with varying density and high dimensions. Great for geospatial data, anomaly detection and non-convex shapes (k-means fails on moons).

Two moons + scattered noise. As the algorithm visits points, the circle shows the ε-neighbourhood being examined. Filled dots = core points, hollow = border points, black × = noise; colours = clusters, spreading along each moon. Right: the k-distance plot used to pick ε.

26 · Gaussian Mixture Models & the EM Algorithm

Unsupervised · Clustering / density estimation (probabilistic) · notebooks/26_gaussian_mixture_em.ipynb · lessons/26_gaussian_mixture_em.py

Family: Unsupervised · Clustering / density estimation (probabilistic)

Definition

A Gaussian Mixture Model says the data was generated by choosing one of K hidden Gaussian components (with probability π_k) and drawing a point from it. Unlike k-means, clusters can be elliptical, differently sized, and assignments are soft: each point has a probability of belonging to every component. It is fitted by Expectation-Maximization (EM).

Intuition

Chicken-and-egg: if you knew which component produced each point, estimating the Gaussians would be easy; if you knew the Gaussians, assigning points would be easy. EM alternates: guess soft assignments with the current Gaussians (E-step), then re-fit the Gaussians using those soft assignments (M-step). The likelihood never decreases.

The math

p(x) = Σ_k π_k N(x | μ_k, Σ_k)
E-step:  r_ik = π_k N(xᵢ|μ_k,Σ_k) / Σ_j π_j N(xᵢ|μ_j,Σ_j)           (responsibility of component k for point i)
M-step:  N_k = Σᵢ r_ik ;  π_k = N_k/n ;  μ_k = Σ r_ik xᵢ / N_k ;  Σ_k = Σ r_ik (xᵢ−μ_k)(xᵢ−μ_k)ᵀ / N_k
log-likelihood  ℓ = Σᵢ log Σ_k π_k N(xᵢ|…): rises monotonically; EM finds a local optimum.
Choosing K: BIC = −2ℓ + p·ln n (printed below). k-means is the special case of equal spherical covariances and hard assignments.

Practical tips

  • Initialise with k-means; regularise covariances (add εI) to avoid collapse onto a single point; restart several times.
  • Used for soft clustering, density estimation, anomaly detection (low p(x)), speaker/background modelling.

What the animation shows

Three overlapping, differently-shaped clusters. Each frame is one EM iteration: ellipses (1σ and 2σ) move/rotate/stretch to fit; point colours blend by responsibility (mixed colours = uncertain). Right: the log-likelihood increasing. The console prints BIC for K = 1…6.

27 · Principal Component Analysis (PCA)

Unsupervised · Dimensionality reduction / feature extraction · notebooks/27_pca.ipynb · lessons/27_pca.py

Family: Unsupervised · Dimensionality reduction / feature extraction

Definition

PCA finds new orthogonal axes (principal components) ordered by how much of the data's variance each one captures. Keeping only the first few components compresses the data with minimal information loss, and makes high-dimensional data visualizable.

Intuition

Hold a flashlight to a 3-D cloud so its shadow on the wall is as *spread out* as possible: that direction is PC1. Equivalently, PC1 is the line that leaves the smallest total squared distance from the points to their projections (the residual lines in the animation). The two views are the same by Pythagoras: variance kept + error = total.

The math

centre X;  covariance C = XᵀX/(n−1);   eigen-decomposition C v_k = λ_k v_k   (or SVD: X = U S Vᵀ, λ_k = s_k²/(n−1))
projection  Z = X V_k        reconstruction  X̂ = Z V_kᵀ + mean        explained variance ratio  λ_k / Σλ
The projection onto unit vector u has variance uᵀCu, maximised by the top eigenvector.
Relatives: kernel PCA (non-linear), probabilistic PCA/factor analysis, ICA, truncated SVD (LSA), t-SNE/UMAP (visual, non-linear), autoencoders.

Practical tips

  • Standardize variables of different units first. Choose components via the scree plot (cumulative variance ≥ 90–95 %).
  • Components are linear mixes: harder to interpret; PCA ignores labels (LDA is the supervised cousin).

28 · t-SNE (Non-linear Embedding for Visualization)

Unsupervised · Dimensionality reduction (visualization) · notebooks/28_tsne.ipynb · lessons/28_tsne.py

Family: Unsupervised · Dimensionality reduction (visualization)

Definition

t-SNE maps high-dimensional points to 2-D so that neighbours stay neighbours. It converts distances into neighbour probabilities in both spaces and moves the 2-D points until the two probability distributions match (minimizing KL divergence).

Intuition

Imagine points repelling each other in the plane, but each pair also attached by a spring whose strength is how similar they were in the original space. Similar points get pulled together into clusters, dissimilar ones pushed apart. Heavy-tailed (Student-t) similarities in 2-D give clusters room to separate ("crowding problem").

The math

High-D:  p_{j|i} = exp(−||xᵢ−xⱼ||²/2σᵢ²) / Σ_k exp(−||xᵢ−x_k||²/2σᵢ²) ,   P = (p_{j|i} + p_{i|j}) / 2n
         σᵢ chosen per point by binary search so the effective neighbour count = perplexity (≈ 5–50)
Low-D:   q_ij = (1 + ||yᵢ−yⱼ||²)⁻¹ / Σ_{k≠l} (1 + ||y_k−y_l||²)⁻¹
Cost:    KL(P||Q) = Σ p_ij log(p_ij/q_ij)          gradient:  4 Σⱼ (p_ij − q_ij)(yᵢ−yⱼ)(1+||yᵢ−yⱼ||²)⁻¹
Tricks: early exaggeration (×12 for 100 iterations), momentum, adaptive gains.

Practical tips

  • For visualization only: distances between clusters and cluster sizes are not meaningful; run with several perplexities and seeds. UMAP is faster and preserves more global structure.
  • Do not use t-SNE coordinates as features for a model.

What the animation shows

240 noisy 8×8 stroke images (64-D, 4 classes). Left: PCA's 2-D linear projection (static) for contrast. Middle: the t-SNE embedding unfolding from a random blob into 4 clusters. Right: the KL divergence falling.

29 · Self-Organizing Map (SOM / Kohonen map)

Unsupervised · Neural clustering & topology-preserving visualization · notebooks/29_self_organizing_map.ipynb · lessons/29_self_organizing_map.py

Family: Unsupervised · Neural clustering & topology-preserving visualization

Definition

A SOM is a grid of neurons, each holding a weight vector living in the same space as the data. Training shows data points one by one; the best-matching unit (BMU) and its grid neighbours are pulled toward the point. The result is a 2-D map in which similar inputs land on nearby cells: clustering and visualization in one.

Intuition

Spread a stretchy fishing net over a cloud of points and keep tugging it toward random points. Early on, tugs are big and affect a wide area (the net finds the overall shape); later tugs are small and local (fine tuning). Here the "points" are random colours: the map organizes itself into a smooth colour atlas, with red next to orange, never next to cyan.

The math

BMU:       c = argmin_k ||x − w_k||
update:    w_k ← w_k + η(t) · h(k, c, t) · (x − w_k)
neighbourhood  h = exp(−||pos_k − pos_c||² / 2σ(t)²)         η(t) = η₀ e^{−t/τ} ,  σ(t) = σ₀ e^{−t/τ}
Quantization error = mean ||x − w_BMU||.  U-matrix (distance between neighbouring cells) reveals cluster borders.

Practical tips

  • Good for exploratory visualization of high-dimensional records (customers, sensor profiles, genes). Hex grids, toroidal maps and batch training are common variants.
  • Modern alternatives for visualization: UMAP, t-SNE. SOM's advantage is a fixed, reusable grid map.

Left: the 14×14 map's weights shown as colours, with the BMU of the current sample ringed and the neighbourhood radius drawn. Right: the roughness (average colour difference between neighbouring cells) collapsing as the map organizes itself.

30 · Isolation Forest (Anomaly Detection)

Unsupervised · Anomaly / outlier detection · notebooks/30_isolation_forest_anomaly_detection.ipynb · lessons/30_isolation_forest_anomaly_detection.py

Family: Unsupervised · Anomaly / outlier detection

Definition

Isolation Forest detects anomalies by how *easy they are to isolate*. It builds many random trees: pick a random feature, pick a random split value between the min and max, and recurse until each point sits alone. Anomalies are few and different, so random cuts separate them in very few splits; normal points deep inside the crowd need many.

Intuition

Play "20 questions" with random questions. To single out a faulty machine whose temperature is far from everyone else, one or two cuts suffice. To single out one typical machine in the middle of a dense cloud you must keep cutting. Short average path length ⇒ anomaly.

The math

path length h(x) = number of edges from the root to the leaf that isolates x   (+ c(size) correction for unfinished leaves)
c(n) = 2(ln(n−1) + 0.5772) − 2(n−1)/n         expected path length in an unsuccessful BST search (the normaliser)
anomaly score  s(x) = 2^{ −E[h(x)] / c(ψ) }    ->  near 1: anomaly,  well below 0.5: normal,  ≈ 0.5: no clear anomaly
Each tree uses a small random subsample ψ (e.g. 256), which makes it fast (linear time) and robust to "swamping".
Related: LOF (local density), One-Class SVM, autoencoder reconstruction error (lesson 20), Gaussian mixture density (lesson 26).

Practical tips

  • Choose the score threshold from the expected contamination rate or business cost; no labels needed.
  • Axis-parallel cuts can create artefacts (Extended Isolation Forest fixes it). Works well on tabular sensor/finance/log features.

What the animations show

1. 30_isolation_forest_anomaly_detection.gif: random cuts isolating an outlier (left, ~3 cuts) vs a normal point (right, many cuts). The red region is the isolated cell. 2. 30_isolation_forest_anomaly_detection_forest.gif: adding trees one by one; the anomaly-score map stabilises and the true faults light up.

31 · Association Rules & the Apriori Algorithm

Unsupervised · Pattern mining (market-basket analysis) · notebooks/31_apriori_association_rules.ipynb · lessons/31_apriori_association_rules.py

Family: Unsupervised · Pattern mining (market-basket analysis)

Definition

Association-rule mining finds items that frequently occur together in transactions and states them as rules "if {bread} then {butter}". Apriori finds all *frequent itemsets* efficiently by growing them level by level and pruning with one key fact: a set can only be frequent if all its subsets are frequent.

Intuition

Count single items first; throw away rare ones. Only combine survivors into pairs; count and prune; combine surviving pairs into triples, and so on. Whole branches of the search space are never counted. Then turn frequent sets into rules and rank them by how much they beat chance (lift).

The math

support(A)        = P(A) = (# baskets containing A) / N
confidence(A→B)   = support(A∪B) / support(A) = P(B | A)
lift(A→B)         = confidence / support(B)     (>1: positively associated, 1: independent, <1: substitutes)
Apriori principle: support(S) ≤ support(T) for any T ⊂ S   ⇒  prune a candidate if any subset is infrequent.
Faster alternatives: FP-Growth, Eclat. Applications: recommendations, store layout, cross-selling, log/alert correlation, web-usage mining.

Practical tips

  • Choose min-support to the order of "enough baskets to matter"; sort rules by lift, not only confidence (popular items inflate confidence).
  • Association is not causation. Beware of many spurious rules at tiny support.

What the animation shows

600 synthetic supermarket baskets with planted patterns (bread→butter→jam, coffee→sugar, diapers→beer, chips→soda). Each stage grows the bars of candidate itemsets; those below the dashed min-support line turn grey and are pruned. The last frames plot every discovered rule: support vs confidence, coloured by lift.

32 · Hidden Markov Models (HMM): Viterbi & Baum-Welch

Probabilistic sequence models (supervised or unsupervised) · notebooks/32_hidden_markov_model.ipynb · lessons/32_hidden_markov_model.py

Family: Probabilistic sequence models (supervised or unsupervised)

Definition

An HMM assumes a system moves through hidden states (not observed) following a Markov chain, and each state emits an observable symbol/measurement. From the visible sequence you can: evaluate its likelihood (forward algorithm), decode the most likely hidden path (Viterbi), and learn the parameters (Baum-Welch = EM).

Intuition

You never see the weather where your friend lives, only what they did each day (walk, shop, clean). Rainy days make cleaning likely, sunny days walking. From a week of activities you can infer the likely weather pattern. In engineering: hidden machine health (healthy/degraded/failing) from vibration readings; speech phonemes from audio; gene regions from DNA.

The math

parameters  π (initial probs), A_ij = P(sₜ₊₁=j | sₜ=i) (transitions), B_i(o) = P(o | state i) (emissions)
Forward:   αₜ(j) = [Σ_i αₜ₋₁(i) A_ij] · B_j(oₜ)                  P(o) = Σ_j α_T(j)      (O(T·N²))
Viterbi:   δₜ(j) = max_i [δₜ₋₁(i) A_ij] · B_j(oₜ) ,  ψₜ(j) = argmax_i ... ;  backtrack from argmax δ_T
Baum-Welch (EM):  E-step: γₜ(i)=P(sₜ=i|o), ξₜ(i,j)=P(sₜ=i,sₜ₊₁=j|o) via forward-backward;
                  M-step: A_ij = Σξ/Σγ ,  B_i(o)=Σ_{t:oₜ=o} γₜ(i)/Σγₜ(i)
Use log-probabilities or scaling to avoid underflow. Modern relatives: CRFs, Kalman filters (continuous states), RNNs/transformers.

33 · Gaussian Processes (GP) Regression

Supervised · Bayesian non-parametric regression · notebooks/33_gaussian_process.ipynb · lessons/33_gaussian_process.py

Family: Supervised · Bayesian non-parametric regression

Definition

A Gaussian process is a distribution over *functions*. You choose a kernel that says how similar the outputs at two inputs should be; conditioning on the observed points gives, at every new input, a full Gaussian predictive distribution: a mean and a calibrated uncertainty. It is regression that knows what it does not know.

Intuition

Draw random smooth curves (the prior). Every time you observe a data point, throw away all the curves that miss it. What remains is a bundle of plausible functions: tight near data, fanning out away from it. The kernel's length-scale decides how wiggly the plausible functions are.

The math

f ~ GP(0, k),    k(x,x') = σ_f² exp(−(x−x')²/2ℓ²)               (RBF kernel)
data (X, y) with noise σ_n:   K = k(X,X) + σ_n² I
posterior mean   μ(x*) = k(x*,X) K⁻¹ y
posterior var    σ²(x*) = k(x*,x*) − k(x*,X) K⁻¹ k(X,x*)
hyper-parameters (ℓ, σ_f, σ_n) are chosen by maximizing the marginal likelihood  log p(y) = −½ yᵀK⁻¹y − ½ log|K| − (n/2) log 2π.
Cost O(n³) in the number of points (sparse GPs / inducing points help). Uses: Bayesian optimization, surrogate models, geostatistics (kriging), small-data science.

What the animation shows

Phase 1: observations arrive one at a time: the mean (red), the ±2σ band and five posterior function samples (thin) tighten around the data. Phase 2: with all data fixed, the length-scale ℓ sweeps from tiny (overfits, wiggly) to huge (underfits, flat), with the marginal likelihood shown so you can see why it picks a middle value.

34 · Matrix Factorization & Recommender Systems

Unsupervised/supervised hybrid · Collaborative filtering · notebooks/34_matrix_factorization_recommender.ipynb · lessons/34_matrix_factorization_recommender.py

Family: Unsupervised/supervised hybrid · Collaborative filtering

Definition

A recommender predicts ratings people *haven't given yet*. Matrix factorization approximates the (mostly empty) user×item rating matrix R by the product of two thin matrices: user vectors U and item vectors V. The rating of user u for item i is predicted by the dot product u·v_i. Each dimension is a learned "taste" (e.g. action vs romance).

Intuition

Users and items live in the same small "taste space". If your vector points the same way as a movie's vector, you'll probably like it. We never tell the model what the dimensions mean: fitting only the *observed* ratings makes similar users and similar items drift together. Here the true taste space is 2-D, so we can literally watch users and movies organise on a map.

The math

R̂_ui = μ + U_u · V_i                       (add user/item biases b_u + b_i in practice)
minimize over U, V:   Σ_{(u,i) observed} (R_ui − R̂_ui)²  +  λ (||U||² + ||V||²)
SGD:      e = R_ui − U_u·V_i ;  U_u ← U_u + η (e V_i − λ U_u) ;  V_i ← V_i + η (e U_u − λ V_i)
Alternating least squares (ALS) solves each side in closed form and parallelizes well.
Evaluate on **held-out ratings** (RMSE). Cold-start problem: no history for new users/items → use content features.
Beyond: implicit feedback (clicks), factorization machines, two-tower neural networks, transformers for sequences.

Panels: (1) the observed ratings (grey = missing), (2) the model's completed matrix as it trains, (3) the 2-D taste space with users (circles) and movies (triangles), (4) train/test RMSE. The completed matrix fills in plausible values for the grey cells, and test RMSE drops without seeing those entries.

35 · Time-Series Forecasting: Smoothing, Holt-Winters & Autoregression

Supervised · Forecasting · notebooks/35_time_series_forecasting.ipynb · lessons/35_time_series_forecasting.py

Family: Supervised · Forecasting

Definition

Time-series models predict future values from the past, exploiting trend (long-run direction), seasonality (repeating cycles) and autocorrelation (today depends on yesterday). We compare three classics on monthly sales: the seasonal-naive baseline, Holt-Winters (triple exponential smoothing) and an autoregressive AR(p) model fitted by least squares.

Intuition

  • Seasonal naive: "next March will look like last March." Hard to beat on simple data.
  • Holt-Winters: keep three running estimates, a *level*, a *trend*, and 12 *seasonal offsets*, each updated by exponential smoothing: recent data counts more.
  • AR(p): regress today on the last p values; with p ≥ 12 it can learn the yearly cycle and the trend from the data itself.

    • Always evaluate with walk-forward (rolling-origin) validation: never shuffle time series, and never train on the future.

The math

Holt-Winters (additive):   ℓₜ = α(yₜ − sₜ₋ₘ) + (1−α)(ℓₜ₋₁ + bₜ₋₁)
                           bₜ = β(ℓₜ − ℓₜ₋₁) + (1−β) bₜ₋₁          sₜ = γ(yₜ − ℓₜ) + (1−γ) sₜ₋ₘ
                           forecast  ŷₜ₊ₕ = ℓₜ + h·bₜ + sₜ₊ₕ₋ₘ
AR(p):  yₜ = c + φ₁yₜ₋₁ + … + φ_p yₜ₋p + εₜ          fitted by least squares; multi-step forecasts feed predictions back in.
ARIMA(p,d,q) = AR + differencing d times (removes trend) + moving-average errors q; SARIMA adds seasonal terms.
Metrics: MAE, RMSE, MAPE, MASE (scaled vs naive).  Modern: Prophet, ETS, gradient boosting on lag features, N-BEATS, transformers.

What the animation shows

The forecast origin walks forward through the history. Top: the next 12 months predicted by each method against the truth. Bottom: running average MAE of each method across origins so far.

36 · Reinforcement Learning: Q-Learning & Bandits

Reinforcement learning (learning from rewards by interaction) · notebooks/36_reinforcement_learning.ipynb · lessons/36_reinforcement_learning.py

Family: Reinforcement learning (learning from rewards by interaction)

Definition

An agent interacts with an environment: it observes a state, takes an action, receives a reward and a new state. The goal is a policy maximizing the long-run (discounted) reward. There is no labelled dataset; the agent must explore to discover what pays off and exploit what it already knows.

Intuition

*Cliff walking*: the agent must get from the start (bottom-left) to the goal (bottom-right). Each step costs −1 (so shorter is better); stepping on the cliff costs −100 and teleports back to the start. Q-learning learns a table Q(state, action) = "how good is this move from here, assuming I act well afterwards". Early on the agent stumbles; later its greedy arrows form a route. *Bandits* are the one-state special case: several slot machines with unknown payout rates; pull them to maximise winnings (A/B testing, ad selection).

The math

Return G = Σ γᵗ rₜ              Q*(s,a) = E[r + γ max_a' Q*(s',a')]        (Bellman optimality)
Q-learning update:   Q(s,a) ← Q(s,a) + α [ r + γ max_a' Q(s',a') − Q(s,a) ]          (off-policy, model-free)
ε-greedy exploration: random action with prob ε, else argmax Q.     SARSA uses the action actually taken next (safer path near the cliff).
Bandit strategies:  ε-greedy ;  UCB1:  argmax μ̂ₐ + √(2 ln t / nₐ) ;  Thompson sampling: sample p̂ₐ ~ Beta(1+wins, 1+losses), pull the argmax.
Regret = Σ (best arm mean − chosen arm mean).      Deep RL replaces the table with a neural network (DQN) or learns the policy directly (policy gradients, PPO, actor-critic).
